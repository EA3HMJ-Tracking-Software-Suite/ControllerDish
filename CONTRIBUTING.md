# Contributing to ControllerDish

Because ControllerDish is a complex project with a wide range of motors, sensors, controllers, mechanical systems, communication methods, and possible configurations, we use GitHub Issues and Pull Requests to manage the application's development more clearly and efficiently.

## Reporting a problem with Issues

Please open one Issue for each bug or feature request. Before opening it, search the existing Issues to avoid duplicates.

For a bug report, please include:

- the ControllerDish version and controller/firmware version;
- the Windows version and communication method;
- the motor drivers, encoders, sensors, and relevant hardware configuration;
- the steps needed to reproduce the problem;
- what you expected and what actually happened;
- relevant logs, screenshots, and configuration details;
- whether the problem happens every time.

Do not publish passwords, tokens, private addresses, or other sensitive information. You are welcome to add comments, test results, or additional hardware details to an existing Issue.

## Proposing changes with Pull Requests

Use a Pull Request when you have a concrete code or documentation change. Keep each Pull Request focused on one subject, explain why the change is needed, and link the related Issue with `Fixes #issue-number` when appropriate.

Please describe how the change was tested and mention any controller or mechanical hardware required for final validation. A Pull Request may remain in draft form while it is being discussed or tested. Maintainers will merge it after review and validation.
